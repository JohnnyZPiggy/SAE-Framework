# Engineer Compute Tool Discovery Gate (SAE V3.3)

> Normative English. This is an Engineer **execution checklist**, not a new approval, daemon, installer, or entitlement. [Compute tool contract](../tools/compute/README.md).

## When this applies
During role recovery, if the assigned Issue mentions a CUDA/GPU/Colab experiment or cannot be accepted without device evidence, complete this checklist **before** declaring GPU unavailable, proposing manual notebook work, or running an improvised Colab command. The first cold-start pass remains **read-only**: locate/read and report; do not allocate, authenticate, install, or test until a separately invoked bounded execution batch.

## Lazy discovery, no diagnostic loop
This gate applies only if the task actually needs Colab/GPU evidence; it does **not** make every Engineer startup a CLI/OAuth audit. During initial read-only recovery, inspect only applicable paths and version information if available without changing state; do not execute preflight. Immediately before a bounded allocation, rerun mandatory live authenticated usage/active-session checks even if previously observed. Do not reuse cached entitlement or session-zero evidence.

Prefer the existing pinned controller and its documented interface. Avoid repeated provider-internal exploration, redundant version probes, cloned diagnostic scripts or new scratch folders when the same result is already established. Keep static environment discovery cached for the unchanged runtime; run fresh authenticated usage/session checks at actual allocation time only. Scratch on the Scientist-designated synced drive is allowed; synchronization itself is not a blocker. Keep each attempt finite and distinguish safe static discovery from privileged live probes. Clean only task-owned scratch, never another run's state.

## Discover, do not assume
1. Identify the actual executing machine: Claude Code local vs remote, Codex local vs cloud, shell OS, current project root, SAE checkout location and exact SAE tool pin. `pwd`, `git remote -v`, `git rev-parse HEAD`, `python --version`, `command -v colab` (or Windows equivalent) are diagnostics, not evidence of remote GPU.
2. Read the target project's `AGENTS.md`, `sae.yaml`, immutable SAE pin (or optional `.sae/` snapshot), and this file plus `tools/compute/README.md`. Explicitly check whether **all three adjacent files** exist at the pinned SAE tool revision: `environment_preflight.py`, `colab_control.py`, `kernel_smoke.py`. A GitHub-visible script is not automatically executable in the agent's environment.
3. Locate the executable in **the same shell where it will launch**. For Windows/WSL, check WSL itself; a working Windows or earlier Codex setup does not transfer to macOS, Claude Code, or Codex Cloud. Check installed CLI version and authenticated state **using documented CLI read-only operations**; do not reveal credentials or attempt login/installation without separate scope.
4. Classify precisely: `TOOL_NOT_PRESENT` (scripts not accessible); `CLI_NOT_INSTALLED`; `CLI_VERSION_UNVERIFIED`; `AUTH_UNAVAILABLE`; `REMOTE_ENV_ISOLATED`; `READBACK_UNVERIFIED`; `SOURCE_SHA_MISMATCH`; or `READY_FOR_PREFLIGHT`. Do not collapse these into “no GPU”.

## Bounded execution batch
1. Get the exact committed algorithm source SHA and an unused local evidence directory, and confirm the controller scripts' immutable SAE pin. Never float to framework `main` or silently upgrade a project's `.sae/`.
2. In a separately requested execution cycle, follow the audited invocation and safety requirements in [tools/compute/README.md](../tools/compute/README.md). Start with `python <pinned-SAE>/tools/compute/colab_control.py --preflight-only --cli colab --repo-path <project> --source-sha <40-hex> --run-id <unique-id> --out <new-output-dir>`. Replace placeholders with observed values; never execute example placeholders literally. This is local-only and makes no allocation.
3. Only if preflight succeeds and the task authorizes a bounded run, use the **project-committed** driver and artifact manifest with the controller (not a hand-built replacement). The generic controller currently supports **T4 requests only**, and requesting T4 does not prove the remote device actually is T4. The project driver must independently report real GPU identity and numerical evidence. Never claim TPU transport is implemented by this controller.
4. Respect one-session default, finite timeouts, authenticated usage/readback requirements, no new billing, SHA-256 artifact checks, mandatory stop and authenticated-zero verification. On errors or interruption attempt cleanup and record a failure if release is unconfirmed.
5. If scripts/CLI are inaccessible, give a **specific remediation targeted at the actual runtime** (e.g., correct WSL shell, checked-out pinned SAE tools, authenticated CLI in that same environment). Do **not** silently create credentials, bypass controller checks, patch provider internals, install unpinned CLI, switch to an unofficial transport, or ask the Scientist to operate Colab as a routine workaround.

## Mandatory handoff
Report: runtime/OS; target repo + source SHA; pinned SAE tools source and existence; CLI path/version/auth-readback (without secrets); preflight status; remote device **observed or NOT RUN**; evidence output and hashes; session cleanup **confirmed / unconfirmed / not allocated**; precise blocker and next action. Separate `SCRIPT_DISCOVERED`, `PREFLIGHT_PASS`, `TRANSPORT_PASS`, `DEVICE_OBSERVED` and `SCIENTIFIC_VALIDATED`: none implies the next. Do not invent evidence.
