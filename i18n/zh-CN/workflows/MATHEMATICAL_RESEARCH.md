# 数学结构探索与张量化研究关口

> 语言：[English](../../../workflows/MATHEMATICAL_RESEARCH.md) | **简体中文**

**主要负责人：GPT 科学导师；科学批准：人类 Scientist。**  
**位置：** 新算法实现或实质性张量化重构的**前置研究阶段**，发生在工程任务派发和正式硬件 Benchmark 之前。

## 研究先于工程

**数学结构探索 → 等价张量数学重构 → 架构与实验设计 → 工程实现 → CPU/GPU 证据验证。**

这是进入工程的**研究关口**，而非不可返回的流水线。Codex 或 Colab 的结果可以随时触发回到数学研究。创建仓库、安装协议等基础设施可以先进行，但在完成前置研究前，不应直接派发算法重写或声称已有硬件加速。

## R1：研究原始数学结构（Mentor + Scientist）
1. 阅读论文、数学定义、目标函数、维度、输入条件、数值契约和现有实现（如果有）。
2. 系统寻找可复用的算子：线性/仿射变换，矩阵向量和矩阵矩阵乘法，张量缩并，可分离结构，独立批次，matrix-free `Ax` / `Aᵀx`，Jacobian-vector / vector-Jacobian / Hessian-vector product，低秩、稀疏、分块、Kronecker、归约和 scan。
3. 分析张量化阻碍：顺序递推、分支、不规则访存、host 同步、计算图断裂、动态形状和数据相关控制流。
4. 区分数学性质与工程猜测；没有证明或证据时，不得保证等价性、速度或跨设备性能。

## R2：推导等价张量数学表达
1. 从参考算法出发**逐步推导**，以明确的指标和张量维度说明原式与候选表达式。
2. 检查等价条件、适用参数域、可微性（按需）、数值稳定性、边界情况、精度及近似带来的偏差。
3. 研究向量化、批量化、广播、缩并/`einsum`、线性算子、`vmap`、batched 分解和函数式控制流；并不是所有循环都应该强行变成稠密张量。
4. 评估渐近复杂度、算术强度、中间内存、并行深度、数据搬运、编译成本、dtype 和 CPU/GPU/TPU 的可移植性。
5. 对比**原始参考算法**、**候选张量表达**与**不可行时的备选方案**。若没有有价值的张量化方案，也应如实记录，这是有效研究结论。

## R3：输出数学研究交接报告
在目标算法仓库中新建或更新 `docs/research/<algorithm>-tensorization.md`，使用 [张量化研究模板](../../../templates/TENSORIZATION_STUDY.md) 的中文版 [说明](../templates/TENSORIZATION_STUDY.md)。

至少包含：
- 原问题、假设、参考算法和目标算子；
- 代数结构、数据依赖与不可并行部分；
- 原式 → 重构式推导、形状/dtype、证明或近似边界；
- 参考正确性判据、反例、容差与数值风险；
- 理论计算量/内存、硬件可移植性假设；
- 待验证的实验问题（不是已测性能）、备选方法与阻碍；
- **结论：RESEARCH_READY / RESEARCH_BLOCKED / NOT_TENSORIZABLE**、依据和科学家审核。

**RESEARCH_READY 只表示数学方案足以进入设计，并不意味着数值正确性已通过实验或已经实现 GPU 加速。** 若结果为 RESEARCH_BLOCKED / NOT_TENSORIZABLE，不得擅自将性能优化 Issue 交给 Codex。Scientist 可以改选方案、允许有限参考实现，或明确记录例外。

## 进入架构师与工程阶段
1. 科学家审核研究报告并选定数学表达。
2. GPT 切换 **Chief Architect**：依据报告设计模块接口、正确性验收、实验矩阵与 Codex 任务。
3. 工程 Issue 必须链接研究报告，并区分**已证明、待验证、尚未测试**的结论。
4. Codex 实现参考版/张量版并真实运行 CPU 检查；之后由科学家对固定 commit 在 Colab 做 GPU/其他设备测试，必要时回到 R1/R2。
5. 前置阶段允许少量**数学合理性检查**用于发现错误，但不能冒充正式工程验收或 GPU Benchmark。

## 「推进导师工作」如何变化？
新项目若没有被科学家认可的研究报告，**优先执行 R1–R3**，而不是直接跳到教学或性能测试。已有方案的项目则可以继续数学教学和发现新结构。一次指令可以只完成一个有边界的研究问题；涉及科学决策请科学家确认。
