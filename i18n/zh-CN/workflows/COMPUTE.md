# 计算——CPU 与 GPU 实验（V3.4）

> [English](../../../workflows/COMPUTE.md) 为规范版本 | 简体中文译本

## 政策：有多少算力就用多少
- **GPU 优先**：适合的张量任务从一开始就规划 GPU 运行，同时保留 CPU oracle 验证正确性。纯 CPU 工作从不因等 GPU 而阻塞。
- **默认运行实验。** 在现有 Colab 权益内，Engineer 直接运行 CPU 和 GPU 任务，无需 Scientist 批准、价格估算或单次预算。
- **SAE 不设配额。** 按研究问题确定规模：账户实际提供的每种 GPU 都可以试，可修复的失败可以重试。小探针是起点，不是上限。
- **真实限制照样适用：** provider 配额和可用性、有限超时、清理，以及**未经用户明确批准不产生新支出**（购买、充值、按量付费）。如果运行可能在现有权益之外产生费用，停下来问。

## 运行一次实验
1. **固定源码。** 运行精确的、已提交的 40 位 SHA。本地未提交的改动要如实标注，不能冒充固定版本的结果。
2. **用控制器运行**（[tools/compute](../../../tools/compute/README.zh-CN.md)）：
   - 一次只开一个会话；分配前确认活动会话为 0、余额为正。
   - 记录**实际观测到**的设备。
   - 无论成功、失败还是 Ctrl-C，都会关闭会话并确认活动会话为 0。
   - 科研计算由项目提交的驱动脚本完成；运行本身不写 GitHub。
3. **交接。** 结果提交到算法项目的 PR，由 Architect 审查并合并。

每个会话第一次真机运行前，先用 `--preflight-only` 在本地检查环境，它不会分配会话。`PROBE_ONLY` 设备检查可以早于 `RESEARCH_READY`，但它只证明设备可用，不证明算法正确或更快。这里**没有实现** TPU / PyTorch-XLA；列表里有 TPU 选项不代表任何东西。

## 证据
不超过[简洁契约上限](../governance/SIMPLICITY_CONTRACT.md#3-证据git-就是完整性层)：每次运行最多 10 个文件，通常两个就够。
- `summary.md`（[模板](../templates/EXPERIMENT_REPORT.md)）：
  - 源码 SHA、Issue/PR、实际观测设备、一行环境、命令、种子和 dtype；
  - 与参考对照的正确性及容差；
  - 计时方法（预热、同步、重复次数、中位数）；
  - 失败列表 `尝试 — 原因 — 修复`；
  - 清理回读。
- 一个结果文件（`results.json` 或 `.csv`），只放 summary 引用的数字。

只对从 Git 之外下载的字节记录 SHA-256。没有同等精度下的等价基线，就不能声称加速。

## 状态
- `PASS`
- `FAIL`
- `NOT RUN`：未尝试，或硬件未测
- `BLOCKED`：真实的权限、配额或计费边界，或源码不匹配
- `CLEANUP_FAILED`：释放未确认，永远不算通过

## 工作区
临时文件、构建和缓存放在 Scientist 指定的工作区，允许 Dropbox 同步的 D 盘。集中在一个任务目录，只删除自己创建的内容。控制器自己的临时导出目录（`--temp-root`）必须在 checkout 之外、Dropbox 之外；有其他盘可用时也不要放在 C 盘。Google Drive 只可作为 Notebook 临时空间，不能用来传递结果。Colab 密钥只放在 Colab Secrets 里，绝不打印到日志。
