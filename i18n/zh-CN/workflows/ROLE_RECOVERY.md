# 每轮工作的角色恢复与完整性检查

> [English](../../../workflows/ROLE_RECOVERY.md)（正式规范） | 简体中文

**用户口令决定当前身份，GitHub 的真实证据决定任务状态。** 新会话或上下文压缩后，先恢复角色、项目、关口和实际权限；不新增 Agent、后台服务或状态数据库。

## 简短恢复顺序

1. **确认项目与身份：** 识别准确算法仓库及 `推进导师工作` / `推进架构师工作` / `推进工程师工作`；不明确就只问一个关键问题，不把 Framework 主仓库默认当算法项目。
2. **读取固定规则：** 项目根 `AGENTS.md`、`sae.yaml` 和不可变 `.sae/` 的共同/角色/流程文档；维护 Framework 自己时读本仓库当前文件。**不得偷偷升级算法项目固定快照。**
3. **查验事实：** 读取当前 GitHub Issue、PR、被测 SHA、数学/工程/GPU 报告与科学家决定，区分真实验收和 Agent 自述；选择一个最高优先级、未阻塞且属于本角色的任务。
4. **检查边界：** 核实 GitHub、CPU/Colab 等本轮**真正可用**的工具、研发关口和 Scientist 实质审批。导师不悄悄代 Codex，Codex 不自我合并，GPT 不假装已替科学家跑 GPU。
5. **执行并交接：** 一轮有边界工作，回写实际 PASS/FAIL/NOT_RUN/BLOCKED 证据，以 [下一步口令](NEXT_ACTION.md)结尾。

## 合并前核验

架构师每次审核都要读取 [当前常设授权](../governance/STANDING_AUTHORIZATION.md)，实时核实 GitHub owner/public 与合并权限。人类授权对 `JohnnyZPiggy` **当前及未来本人全部公开仓库**长期有效，**不需逐仓库登记或逐 PR 再请示**；私有/他人仓库不涵盖。满足 T1/T2/T3 证据与 Scientist 保留的**实质内容决定**后，架构师自主决定最终是否合并。新的用户撤销指令优先于旧快照。

无法读取 GitHub/协议就写 `UNVERIFIED`，缺失审批或真实执行就写 BLOCKED/WAITING，不能猜测。正常情况不展示冗长自检，只有角色冲突或阻塞时说明。
