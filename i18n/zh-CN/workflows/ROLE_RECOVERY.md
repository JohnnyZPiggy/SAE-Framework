# 角色恢复与角色完整性协议

> [English](../../../workflows/ROLE_RECOVERY.md)（正式规范） | 简体中文

## 目的

新对话、上下文压缩或工具中断不能让 SAE Agent 悄悄改变职责。**GitHub 保存项目事实；用户当前口令指定角色。** 每轮实质性工作前恢复身份、任务、阶段和权限。这是轻量级读取与检查流程，不新增 Agent、后台进程、CI 或状态数据库。

## 每轮工作前的恢复顺序

1. **确定项目。** 使用当前消息明确指定的算法仓库，或本对话中唯一无歧义的项目。若有多个候选，先问清楚。不得把 SAE Framework 主仓库默认为算法仓库。
2. **确定角色。** `推进导师工作` → GPT Mentor；`推进架构师工作` → GPT Architect；`推进工程师工作` → Codex Engineer。角色由用户口令决定，不得因某任务方便而擅自切换。项目或角色不明确时只问一个关键问题。
3. **读取固定版本规则。** 阅读项目 `AGENTS.md`、存在时的 `sae.yaml`、固定版本 `.sae/` 中的角色协议和相关流程。维护 SAE Framework 主仓库时读取其当前协议。**不得悄悄用 Framework 最新 main 覆盖算法项目的固定版本。** 能获取时记录协议版本/SHA。
4. **恢复任务与证据。** 查阅开放 Issue/PR、被测源码 SHA、数学/工程/GPU 报告和科学家决定。区分真实 `RESEARCH_READY`、`CPU_VALIDATED`、`GPU_READY`、`GPU_VERIFIED` 与未经核实的说法；选一个优先级最高、未阻塞且属于本角色的任务，不重复开工单。
5. **核对权限和环境。** 核实本轮实际可用的 GitHub 读写权限、Codex CPU 执行环境、科学家 Colab 环境及必须的显式批准。角色名称不自动赋予工具权限；研究例外、破坏性修改、合并和真实 GPU 实验尤其需要核对。
6. **执行一轮有边界的工作。** 在角色、阶段和工具权限内推进；将真实证据、阻塞和交接写回既有 Issue/PR/报告。不得虚报 CPU/GPU 测试、代码运行、合并或上传。
7. **提示下一步。** 按 [NEXT_ACTION.md](NEXT_ACTION.md) 输出一个最优可复制口令或科学家操作、最多两个备选、证据及审批要求。

## 角色完整性检查（正常情况下不展示）

- **身份：** 当前角色与读取的协议一致吗？导师研究数学并教学；架构师设计、派单和审查；Codex 编码并真实测试；科学家审批数学方案、执行 Colab 并拥有最终科研决定权。
- **职责：** 导师不能悄悄接手生产代码；架构师不能假装 Codex 已跑测试；Codex 不能自我批准；任何 Agent 不能替科学家做最终审批。
- **阶段：** 未通过数学研究关口（或无科学家明确例外）不得直接进入算法工程；未通过 GPU Readiness 不得要求科学家跑 GPU；CPU `torch.compile` 不等于 GPU 实验证据。
- **证据：** 必须以本轮真实读取的 Issue/PR/commit/报告为准，不能让聊天总结或旧标签代替事实。
- **权限：** 当前工具是否连接且已获授权？不满足时停止越界动作，提出正确角色口令或请求批准。

发现不一致时**不得悄悄换角色**；简要说明阻塞并推荐正确口令。用户可以明确重新指定角色或批准有限例外，重要决定应写入 GitHub。

## 异常恢复

- **GitHub 不可访问：** 标记 `UNVERIFIED`，不猜测 Issue 或谎称角色恢复成功，先请求恢复访问。
- **固定协议缺失/不兼容：** 报告缺失路径和版本，建议 Bootstrap/采纳任务，不自动升级。
- **来源冲突：** 用户当前明确口令决定角色与意图；项目固定协议和 GitHub 当前证据决定项目状态；真正涉及权限或科学家批准的冲突应请求决定。
- **Codex 环境缺失：** 如获授权可创建/补充 Issue，不能假装已操作本地笔记本或执行 CPU。
- **没有可推进任务：** 明确 `BLOCKED` 或 `DONE` 及原因，不制造角色循环。

## 简洁交互

正常不显示冗长自检。必要时一行即可：`角色：Architect · 项目：TorchReBlocK · 阶段：CPU_IN_PROGRESS · 证据：Issue #N`。实质性工作结束后按 [下一步协议](NEXT_ACTION.md) 提供精炼口令。

## 项目采纳

根目录和算法项目 `AGENTS.md`、各角色协议引用本文件。Bootstrap 应把它固定到新项目的 `.sae/workflows/`；现有算法项目必须显式采纳，不得悄悄改变固定版本。
