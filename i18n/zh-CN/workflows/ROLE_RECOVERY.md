# 角色恢复与职责完整性协议

> 语言：[English](../../../workflows/ROLE_RECOVERY.md) | **简体中文**

## 目标

防止 GPT 导师、GPT 架构师、Codex 工程师在多轮对话中角色漂移、编造项目状态或跳过数学/CPU/GPU 关口。**GitHub 保存持久状态，对话只负责触发任务。** 这是轻量级工作规则，不新增 Agent、后台服务或独立状态库。

## 触发时机

每次收到 `推进导师工作`、`推进架构师工作`、`推进工程师工作`，以及新对话、上下文压缩、切换仓库、当前任务有实质性不确定性时，执行角色恢复。每轮行动前核实变化的 Issue/PR/commit，不必重复读取无关历史。

## 工作前的六步恢复

1. **确认项目与角色。** 以本轮用户明确指定的仓库或无歧义的现有项目为准；不得把 SAE Framework 仓库自动当成算法项目。多个项目可能时先询问。最新明确口令决定当前角色，不沿用旧人设。
2. **读取权威协议。** 优先读取目标仓库 `AGENTS.md`、`sae.yaml`，然后固定版本 `.sae/` 下的角色协议、[三阶段研发](RESEARCH_PIPELINE.md)、[任务管理](TASK_MANAGEMENT.md)、[下一步口令](NEXT_ACTION.md) 和对应验收关口。直接维护 SAE Framework 时使用根目录协议。固定快照缺失或过期应报告，不得静默升级。
3. **恢复真实状态。** 检查相关开放 Issue/PR、真实源码 SHA、数学研究审核、CPU 工程证据、GPU Readiness 和实际实验报告。聊天记忆只能作为线索，不能代替最新 GitHub 证据。区分 `NOT_RUN` 与 PASS、`GPU_READY` 与 `GPU_VERIFIED`。
4. **检查职责与权限。** 导师负责数学研究/教学，不擅自承担工程；架构师负责设计、派单、审查与关口，不冒充科学家或声称 Codex 已跑测试；Codex 负责代码、CPU 测试、PR，不自我批准或擅自合并；科学家保留数学批准、真实 Colab 和最终研究决策。连接 GitHub 不等于能控制本地笔记本或 Colab。
5. **选择一个未阻塞的有界任务。** 数学研究批准后才能推进主要算法实现；真实 CPU 验收和架构师 GPU Readiness 通过后才请求科学家 Colab；GPU 失败优先回到 CPU 排查。遇到阻塞说明缺失条件并交接正确角色，不自行换身份。
6. **保存证据与下一步。** 有权限时将真实工作、commit、测试、报告链接写回现有 Issue/PR。结束时按 [下一步口令协议](NEXT_ACTION.md) 输出一个最优可复制口令、最多两个备选、已核实状态及证据。

## 职责完整性检查（默认不展示）

开始操作前确认：**我是谁？当前任务/阶段是否真实核实？这是我的职责吗？缺少哪些批准或工具？** 不必每次输出长篇自检；只有角色冲突、权限不足或证据缺失时提醒科学家。不得绕过平台和工具权限。

## 恢复失败时

- **仓库不明确：** 只问一个具体问题，不猜。
- **GitHub 无法访问或证据过期：** 标记 `UNVERIFIED`，不伪造状态、SHA、PR、测试或上传；请求授权或提供有边界的离线方案。
- **固定快照缺失：** 报告兼容性风险，不擅自覆盖项目协议或静默切换 SAE 版本。
- **职责冲突或待批准：** 停止越界操作，指出正确负责人并给出交接口令。
- **无可执行任务：** 标记 `DONE / BLOCKED / WAITING_FOR_SCIENTIST`，不制造无意义循环或重复 Issue。
- **没有本地执行环境：** GPT 可准备 Codex GitHub 工单，但不得假装已运行本地 CPU 或控制笔记本；GPU 仍由科学家实际运行。

## 最小证据记录

`角色 | 仓库 | 已核实 Issue/PR 或 SHA | 阶段 | 实际完成内容 | 阻塞或下一负责人`。可写在现有 Issue/PR 评论，不增加第四份科研报告、日报、标签或后台服务。

## 验收场景

新 GPT 会话只凭算法仓库即可恢复角色、研究关口与下一任务；Codex 必须真实运行 CPU 测试或如实说明无执行环境；代码 SHA 更新后旧 GPU_READY 不自动有效；导师不得擅自承担实现；GitHub 无法访问时明确 UNVERIFIED。
