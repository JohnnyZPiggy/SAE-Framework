# 下一步口令：每轮一个明确动作

> [English](../../../workflows/NEXT_ACTION.md)（正式规范） | 简体中文

导师、架构师或 Codex **每轮实质工作结束**，给科学家一段简短、可查证的交接。这是展示规范，**不是后台调度器或自动下一轮执行授权**。

## 结束时必须包含

- **项目与已证实状态：** 准确仓库、Issue/PR/head SHA 或报告；读取失败写 `UNVERIFIED`。
- **本轮真实完成：** 做了什么，测试 PASS/FAIL/NOT_RUN/BLOCKED，阻塞是什么；不能把计划写成已执行。
- **唯一优先下一步：** 一个可复制的精确口令（如 `推进工程师工作：Issue #N`）或科学家需要做的明确科研/Colab 操作；最多两个真实备选。
- **实质决策依赖：** 仅在数学、安全或数据公开等 Scientist 负责的事项未决定时请其批准内容。**不要对已在常设合并授权内的 PR 重复要求合并许可**，也不在 `GPU_READY` 前频繁请求 GPU。

## 精简示例（仅供格式说明）

> **SAE · 下一步行动**  
> **状态：** CPU_IN_PROGRESS · Issue/真实 SHA  
> **已完成：** 真实证据或 NOT_RUN  
> **推荐：** `推进工程师工作：修复 Issue #N 的 CPU oracle 测试`  
> **阻塞：** 无 / 需 Scientist 作出的具体科学决定

下一步基于真实 GitHub 任务与 [角色恢复](ROLE_RECOVERY.md)。没有可推进任务就写 DONE/BLOCKED/WAITING，不编造任务；仅在客户端支持时提供一键操作。
