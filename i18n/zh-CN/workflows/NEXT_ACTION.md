# 下一步口令协议 — Agent 交接与手机一键继续

> 语言：[English](../../../workflows/NEXT_ACTION.md) | **简体中文**

## 目标

每次 GPT 导师、GPT 架构师或 Codex 工程师完成**实质性的一轮工作**，必须用简短的行动区告诉科学家下一步如何继续。这是**交互与交接规范**，不是新增 Agent、自动调度器、独立状态数据库，也不授权后台自行执行任务。

## 统一输出格式

> **SAE · 下一步行动**  
> **当前状态：** <已核实阶段/状态或 UNKNOWN> · **证据：** <GitHub Issue/PR/报告链接或 NOT_VERIFIED>  
> **推荐：** <可直接复制的中文口令或科学家操作> — <一句理由>  
> **备选：** <零至两条真正有价值的口令>  
> **需要科学家：** <批准 / Colab / 选择 / 无>

- 存在可执行下一步时**只推荐一个最优行动**；全部完成、被阻塞或等待外部事件时明确标记 `DONE / BLOCKED / WAITING_FOR_SCIENTIST`，不得编造任务。
- 总选项**最多三项**：一项推荐，最多两项不同备选。移动端尽量控制在 4–6 行，选项清楚时只给一项。
- 使用**精确可复制口令**：`推进导师工作：<数学问题>`、`推进架构师工作：<审查或派发目标>`、`推进工程师工作：<Issue 编号或实现目标>`；下一步属于科学家时写 `Scientist：<批准或真实 Colab 操作>`。没有真实连接的工具权限，不能声称 GPT 可直接操控本地 Codex 或笔记本。
- 根据**真实 GitHub 状态、优先级、依赖、阶段关口和权限**推荐，不能循环派单、重复过期建议或把推荐当作已执行。
- `RESEARCH_BLOCKED` 优先导师/科学家；`RESEARCH_READY` 转架构师；`CPU_IN_PROGRESS` 转 Codex；`CPU_VALIDATED` 转架构师审核 GPU Readiness；`GPU_READY` 才由**科学家**运行 Colab；`GPU_BLOCKED` 先让 Codex/架构师在本地排查。更高优先级的正确性/安全问题可以覆盖默认规则。
- 当前状态必须有 Issue/PR/commit/报告证据；GitHub 无法访问时写 **UNVERIFIED** 并提示先恢复权限，不得伪造链接或执行结果。
- 客户端若**实际支持交互控件**，可提供与文字口令完全相同的一键操作；Codex、终端或不支持的客户端始终使用纯文字口令。不能保证所有客户端都显示按钮。
- `GPU_READY` 前不得请求反复 Colab 实验；不得擅自合并、泄露凭据或承诺后台执行。科学家保留审批与 GPU 实验权。

## 示例（仅演示，不是实际项目状态）

**SAE · 下一步行动**  
**当前状态：** CPU_VALIDATED（示例）· **证据：** 示例 Issue #42  
**推荐：** `推进架构师工作：审核 Issue #42 的 GPU Readiness` — 先核验 CPU 证据。  
**备选：** `推进工程师工作：复核 Issue #42 的 CPU 编译日志`  
**需要科学家：** 架构师确认 GPU_READY 前暂无操作。

## 与现有协议关系

GitHub Issue/PR 仍是任务交接的唯一正式记录；本协议仅统一每轮结束时**告诉科学家什么**。根目录和项目 AGENTS、角色协议应链接此文件，不需要在每份角色协议复制全文。

## 角色恢复与防止出戏

每轮实质性工作开始前执行 [角色恢复与完整性协议](ROLE_RECOVERY.md)，根据用户口令恢复身份、读取固定版本和 GitHub 当前证据、核验阶段与权限；若角色不匹配，应报告并交接，不得悄悄切换或虚报执行。每轮结束仍按下一步口令协议交接。
